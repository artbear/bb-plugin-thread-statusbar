# Thread Statusbar

Плагин читает публичные события и контекст открытого треда; для завершённого Codex turn без baseline собственный read-only host entry точечно восстанавливает официальный native итог. Для объяснения формул и ограничений прочитай [README](../../README.md#как-считаются-показатели). Для диагностики используй результаты плагина и вымышленные fixtures; ручное чтение conversation stores и auth не требуется.

1. Установи, какой провайдер выбран: поддержаны только `codex` и `acp-cursor`. Строка принадлежит существующему треду над composer.
2. Раскрой строку кнопкой либо Tab → Enter/Space. `—` означает неизвестное значение; `≈` — оценку контекста. Для активного Codex нужен baseline; завершённый Codex допускает только подтверждённый native итог. При отсутствии rollout, несовпадении session/checkpoint/root/terminal или неподдержанном формате остаётся `—`. Начало хода и его полная длительность берутся из BB. Cursor измеряет символы, не токены.
3. При недоступности данных проверь состояние соединения BB. После reconnect плагин сверяет историю заново. Не делай вывод о зависании по отсутствию текста.
4. Для проверки исходников выполни `npm run check` в checkout с установленными dev dependencies и BB CLI. Для интеграции используй штатные `bb plugin list` и `bb plugin build`; управление установкой определяется поручением пользователя.

Собственный RPC completedOutput принимает только threadId/BB turnId. Server определяет host и native IDs, host возвращает только проверенные IDs/output без текста/путей/сырых ошибок. CLI-команд, настроек, фонового коллектора и записей в тред нет. Точные ограничения поиска, приватность и источник описаны в README. Завершай диагностику указанием подтверждённого источника отсутствия данных либо конкретной непроверенной границы; не подменяй неизвестные counters оценками.
