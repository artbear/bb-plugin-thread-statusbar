# Автономные решения

## Поверхность и scope

Вопрос: модифицировать Desktop или UI BB? Пользователь просит статусную строку в тредах BB для Cursor и Codex. Текущий SDK имеет native experimental_threadContextSegment. Выбрана одна штатная строка над composer; overlay/DOM, собственные панели и настройки не нужны. Пересмотр — если API BB изменится.

## Значение скорости

Референс считает official output по объединению model windows. Нормализованные BB reasoning события могут иметь синтетические короткие timestamps; требовать одинаковую точность нельзя. Выбрана простая проверяемая средняя выдача Codex за полное время хода с явной подписью о tools/wait. Полный baseline обязателен, неизвестное значение не угадывается. Это не model decode benchmark.

Cursor ACP пока не гарантирует token counters. Вместо конверсии текста в токены показываются Unicode символы в секунду за полный ход, с другой единицей. Неизвестные token/cache/context поля остаются —. Пересмотр — когда фактическая ACP версия начнёт отдавать официальные счётчики; отдельная интеграция с Dashboard/Admin API не добавляется.

## Источники и границы

Публичные SDK события и состояние BB дают turn identity, временные метки и доступные usage/context. Новых ключей, сканеров домашнего каталога и private API не требуется. Bounded replay при неполноте отключает зависимую метрику. TTFT и квоты исключены, чтобы ограничить v1 запрошенной строкой.

## Организация и публикация

Пользователь прямо поручил параллельные сабтреды, независимую рецензию и публичный GitHub repository. Исследования разделены, реализация изолирована worktree, review запускается свежим thread без fork истории. Отсутствующие to-spec/to-tickets/implement заменены их контрактами из autonomous-development; план/спецификация/тикеты сохранены локально. Marketplace не поручен и не входит в выпуск.
