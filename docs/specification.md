# Thread Statusbar v1

Утверждённый контракт от 2026-10-30. Плагин BB показывает компактную статусную строку в открытых тредах Codex и Cursor, по образцу [CodexStatusbar](https://github.com/dongyue-19/codex-statusbar). Результат публикуется в новом публичном репозитории `artbear/bb-plugin-thread-statusbar`.

## Результат для пользователя

Одна штатная строка контекста над composer: провайдер и модель, состояние BB, длительность текущего либо последнего хода, средняя скорость, суммарные токены, доля кеша и заполнение контекста. При недостатке места допускается перенос. Поля читаемы в светлой/тёмной теме и узкой панели. Строка не перекрывает ввод и штатные элементы BB.

Строка регистрируется через `experimental_threadContextSegment`, только для provider id `codex` и `acp-cursor`. Никакого DOM scraping, desktop overlay, собственного composer, sidebar/dashboard или настроек. Несколько открытых тредов используют собственные props.threadId и независимое состояние. New thread и редакторы queued messages не входят в поверхность плагина.

Иллюстративный Codex: `Codex · gpt-… · Работает · 00:42 · сред. 18 ток/с · Всего 126k ток · Кеш 72% · Контекст 31k/475k`.

Иллюстративный Cursor: `Cursor · auto · Готов · 00:12 · 28 симв/с · Токены — · Кеш — · Контекст —`.

## Значение показателей

**Ход** — одна попытка выполнения, идентифицированная lifecycle BB. Время от `turn/started` до текущего времени либо соответствующего завершения включает инструменты, reasoning и ожидание внутри хода. Время в очереди до начала не учитывается. Не брать начало из создания/обновления треда или времени открытия UI.

**Скорость Codex** — прирост официального cumulative `outputTokens` за текущий/последний ход, делённый на полную длительность того же хода. Подпись `сред. … ток/с`, доступное пояснение: «Средняя выдача за весь ход, включая инструменты и ожидания; не скорость декодирования модели». Это намеренно другая метрика, чем model-window TPS исходного Desktop overlay: BB может синтезировать короткие reasoning окна. `reasoningOutputTokens` не прибавлять к output повторно.

Для числителя необходим достоверный baseline до начала хода и согласованный счётчик той же provider session. Первый увиденный cumulative snapshot нельзя целиком приписывать текущему ходу. Без baseline, при reset, неполной истории или противоречивых counters скорость недоступна. Доказанную новую сессию с нулевым baseline можно поддержать; предположение «первый прочитанный snapshot значит ноль до него» запрещено. Не использовать `last` как сумму нескольких model responses за весь агентный ход. Повторное usage-событие не увеличивает числитель. Новый ход не наследует скорость предыдущего.

**Скорость Cursor** — количество Unicode code points видимого текста основного хода из `item/agentMessage/delta`, делённое на полную длительность этого хода. Единица только `симв/с`, пояснение о полном времени хода и наблюдаемых событиях. Это полезная скорость текста при отсутствии токенов; нельзя преобразовывать символы в токены или показывать её как tok/s. Исключить reasoning, stdout инструментов, дочерние/фоновые ходы; повторные completed-item snapshots и replay не удваивают текст.

**Суммарные токены** — последний корректный официальный total snapshot: `inputTokens + outputTokens`. Cached input уже входит в input; reasoning уже входит в output. Snapshots заменяют друг друга, не суммируются. Это расход сессии, не заполнение контекста.

**Кеш** — `cachedInputTokens / inputTokens * 100` из того же total snapshot. При input=0 либо неизвестных counters — `—`; при реальном cached=0 и положительном input — `0%`. Некорректные/отрицательные/нечисловые counters и cached>input не превращать в правдоподобные значения.

**Контекст** — последнее provider measurement `usedTokens / modelContextWindow` из публичного `threads.context()` либо context event. Сохранить признак `estimated` как `≈`. Не вычислять контекст из cumulative totals и не угадывать ёмкость по названию модели.

**Модель** — зарегистрированное BB исполнение текущего/последнего хода, с учётом подтверждённого model fallback если доступно. Выбор модели для следующего сообщения не переименовывает уже выполняющийся ход. `auto` допустимо, это не утверждение о фактической backend-модели. Неизвестная модель — `—`.

**Состояние** — состояние BB, включая ожидание, запуск, работу, остановку, готовность, ошибку. Не объявлять «завис» из-за отсутствия deltas. Завершённые/ошибочные/прерванные ходы перестают увеличивать elapsed и сохраняют последнюю пригодную скорость; новый ход сбрасывает turn metrics. Если время окончания неизвестно, не продолжать таймер как у активного хода и не выдумывать время завершения.

**Недоступно** означает `—` с доступным объяснением в штатном раскрытии/подсказке, не ноль. Корректный ноль остаётся нулём. Подсказка определения метрик доступна с клавиатуры, не только по hover.

## Чтение и жизненный цикл

Использовать только публичный SDK установленного BB 0.48 / Plugin SDK 0.6.94. Backend entry может быть пустым, если весь read-only flow обслуживается browser SDK. Не читать auth/session файлы, внутреннюю БД и private endpoints. Данные остаются в BB, новых аккаунтов/ключей не требуется.

При открытии восстановить релевантную историю через `threads.events.list`, с типовыми фильтрами, курсорами, пагинацией и явным пределом объёма. Продолжать инкрементально по seq; callbacks старого треда после переключения не применяются. Отсутствие lifecycle start/baseline/полного текста из-за лимита backfill означает недоступность соответствующей метрики, а не видимость полного измерения. Не опрашивать все треды и не читать историю закрытых тредов.

Дедупликация и восстановление должны быть идемпотентны по sequence/id. Смена provider identity, очистка истории/контекста и reset счётчиков не выдают старые данные за новые. На reconnect сверять источник заново. При ошибке чтения показать недоступность/устаревание и не выдавать сохранённые цифры за актуальные. Уничтожать таймеры, подписки и запросы при unmount/reload; late promises игнорировать. Опрос не должен создавать перекрывающиеся запросы либо бесконечную загрузку всей истории.

## Приёмка и тестовые швы

1. SDK registration и реальный UI: native segment виден у Codex/Cursor, отсутствует у других провайдеров. В двух тредах/панелях цифры не смешиваются; navigation и reload корректны.
2. Сценарии start → tool/wait → complete/error/interrupt → next turn: elapsed привязан к нужному turn, замораживается и восстанавливается из истории. Повторное открытие не начинает отсчёт заново.
3. Детерминированный trace: baseline output=100, в текущем ходе output=160, duration=10s → 6 ток/с; инструмент внутри этих 10s входит в знаменатель. Duplicate snapshots и несколько model responses не удваиваются. Без baseline — `—`; counter reset не даёт отрицательной или ложной скорости.
4. Cursor trace: видимые `А🙂` + `Б` за 2s → 1.5 симв/с (3 Unicode code points). Reasoning, stdout, completed snapshots, child events и duplicates не влияют. Неполная история не выдаёт частичный count за полный.
5. input=1000, output=200, cached=400 → всего 1200 ток, кеш 40%; context=300/1000 → 30%. Проверить нули, отсутствующие/некорректные поля, estimated context.
6. Пустой тред, отсутствие начала, одинаковые timestamps, tool-only ход, ошибки запроса, reconnect, clear/reset, более одной страницы, предел backfill и stale response при переключении не приводят к NaN/Infinity, неверному счёту или аварии composer.
7. Typecheck, существенные поведенческие тесты (SDK harness + чистое вычисление), public-SDK import scan и `bb plugin build` проходят. Повторная сборка из чистой установки без dev dependencies проверяет Git install contract. Live install/reload и браузерные smoke для двух provider ids, узкой панели и темы подтверждены отдельно от fixtures.
8. Публичный репозиторий содержит финальные исходники, тесты, README с точным методом/ограничениями/командой установки, лицензию, спецификацию, план и журнал решений. Секретов и пользовательских auth/transcript dumps нет. Публикация — новый GitHub repository, без marketplace submission.
